# Lab 01 – Deploy a Static Website with Azure Blob Storage

## ☁️ Overview

This lab demonstrates how to deploy and manage a static website using **Azure Blob Storage**. The lab covers creating an Azure Storage Account, enabling static website hosting, uploading HTML content, configuring a custom error page, and updating the website content.

## 🎯 Objectives

* Create an Azure Resource Group
* Create and configure an Azure Storage Account
* Enable static website hosting
* Upload website files to the `$web` container
* Configure a custom `404.html` error page
* Verify the live website and error handling
* Update published website content
* Review blob properties, content type, and access tier

## 🛠️ Azure Services & Technologies

* **Microsoft Azure**
* **Azure Resource Groups**
* **Azure Storage Account**
* **Azure Blob Storage**
* **Static Website Hosting**
* **HTML**

---

## 1. Prepare the Azure Environment

Created a Resource Group to organize the resources used in this lab.

**Resource Group:**
`rg-gp-static-website`

The Storage Account was created in the same Azure region as the Resource Group.

---

## 2. Create the Storage Account

Created a Storage Account configured for static website hosting.

| Setting         | Configuration                   |
| --------------- | ------------------------------- |
| Resource Group  | `rg-gp-static-website`          |
| Storage Account | `stgpstaticsite64465231`        |
| Storage Type    | Azure Blob Storage              |
| Performance     | Standard                        |
| Redundancy      | Locally-redundant storage (LRS) |

---

## 3. Enable Static Website Hosting

Static website hosting was enabled from the Storage Account's **Static website** settings.

| Setting        | Value        |
| -------------- | ------------ |
| Static Website | Enabled      |
| Index Document | `index.html` |
| Error Document | `404.html`   |

Enabling the feature automatically created the special `$web` container used to store the website files.

The **Primary endpoint** generated by Azure was used to access the website publicly.

---

## 4. Upload Website Content

### Version 1

Created an `index.html` file containing the initial landing page and uploaded it to the `$web` container.

The initial website displayed:

> **Version 1 - Landing Page**

A custom `404.html` file was also created and uploaded to provide a user-friendly error page for nonexistent URLs.

The `$web` container contained:

```text
$web/
├── index.html
└── 404.html
```

---

## 5. Validate the Website

The Primary endpoint was opened in a browser to verify the deployment.

### Landing Page

The website successfully displayed:

* `Version 1 - Landing Page`
* Initial welcome message

### Custom 404 Page

A nonexistent path such as `/fakepage` was used to test error handling.

The custom error page successfully displayed:

* `404 - Page Not Found`
* A link back to the home page

The home page link was also tested and successfully returned to the landing page.

---

## 6. Update the Website Content

The original `index.html` was updated to create **Version 2** of the website.

The updated page displayed:

> **Version 2 - Landing Page**

The updated `index.html` was uploaded to the `$web` container with **Overwrite** enabled, replacing the previous version.

After refreshing the Primary endpoint, the updated content was successfully displayed.

---

## 7. Review Blob Properties

The properties of `index.html` and `404.html` were reviewed to understand how Azure Blob Storage manages website files.

| Property     | Value       |
| ------------ | ----------- |
| Content Type | `text/html` |
| Access Tier  | `Hot`       |

The blob URL and raw HTML content were also reviewed through the Azure Portal.

## 💡 Key Takeaways

* Azure Blob Storage can host static websites without requiring a traditional web server.
* The `$web` container is used to store files for an Azure static website.
* `index.html` acts as the default landing page.
* A custom error document can improve the user experience when a requested page does not exist.
* Website content can be updated by overwriting existing blobs.
* Blob properties such as **Content Type** and **Access Tier** affect how stored files are handled and served.
